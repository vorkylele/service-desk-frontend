# service-desk-frontend

Портал самообслуживания для внутренних заявок сотрудников — клиентская часть учебного проекта
к выпускной квалификационной работе «Автоматизация обработки внутренних заявок сотрудников в организации
на примере ООО «ВБ ТЕХ»».

Связанные репозитории:

| Репозиторий | Назначение |
|---|---|
| [service-desk-backend](https://github.com/vorkylele/service-desk-backend) | REST API, прикладная логика, схема базы данных |
| **service-desk-frontend** (этот) | портал самообслуживания (React) |
| [service-desk-autotest](https://github.com/vorkylele/service-desk-autotest) | автотесты API, базы данных и интерфейса, полный стенд в Docker |

## Что делает

- **Регистрация заявок** — каталог услуг с нормативами срока и составная форма: общая часть заполняется
  автоматически из учётной записи, переменная часть зависит от вида заявки.
- **Согласование и исполнение** — решения согласующих (отказ требует причины), очередь и журнал заявок,
  карточка с маршрутом согласования, историей и действиями исполнителя и заявителя.
- **Контроль** — реестр прав доступа со следом предоставления и отзыва, отчёты по нормативам срока
  и нагрузке, кадровое событие «увольнение».

## Стек

React 18 · TypeScript 5 · Vite 4 · React Router 6. Без UI-библиотек: стили — в `src/styles.css`.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173, запросы /api проксируются на http://localhost:8080
npm run build      # проверка типов и сборка в dist/
```

Для работы нужен запущенный `service-desk-backend`. Учётные записи — в его README (пароль `demo`).
В контейнере приложение раздаёт nginx (`Dockerfile`, `nginx.conf`), запросы `/api` уходят на сервис `backend`.

## Структура

```
src/
  api.ts         клиент REST-интерфейса: токен в заголовке Authorization, единый разбор ошибок
  auth.tsx       контекст текущего пользователя
  types.ts       модели данных REST API
  components/    StatusBadge, ErrorAlert
  pages/         экранные формы
```

## Экранные формы

| Страница | Файл | Назначение |
|---|---|---|
| Вход | `pages/Login.tsx` | аутентификация, токен хранится в памяти сеанса браузера |
| Каталог услуг | `pages/Catalog.tsx` | виды заявок с нормативами срока |
| Новая заявка | `pages/NewTicket.tsx` | составная форма: общая часть заполняется автоматически, переменная зависит от вида |
| Мои заявки / очередь / журнал | `pages/Tickets.tsx` | списки с контролем просрочки |
| Карточка заявки | `pages/TicketCard.tsx` | маршрут согласования, история, действия исполнителя и заявителя |
| Согласования | `pages/Approvals.tsx` | решения согласующего; отказ требует причины |
| Реестр прав доступа | `pages/AccessRegistry.tsx` | след предоставления и отзыва прав |
| Отчёты | `pages/Reports.tsx` | нормативы срока, нагрузка на исполнителей |
| Работники | `pages/Employees.tsx` | кадровое событие «увольнение» |

`docs/screenshots/` — эталонные снимки экранов контрольного примера. Они формируются автотестами
(`./gradlew test publishScreenshots` в репозитории service-desk-autotest).
